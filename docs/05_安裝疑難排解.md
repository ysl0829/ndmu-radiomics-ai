# 安裝疑難排解

> 以下每一條都是實際跑過、看過錯誤訊息才寫的，不是推測。
> 最後驗證：2026-09-13。

---

## 狀況 A｜`nvidia-smi` 有輸出，但 `torch.cuda.is_available()` 回 `False`

**原因**：自己裝的框架版本與 CUDA 對不上。

**處置**：不要升級 Colab 預裝的深度學習套件 —— 預裝組合是搭配過的，動它就會壞。重開執行階段，回到預設環境再試。

本課程的 `requirements.txt` **刻意不含 torch / torchvision**，就是為了避免這個狀況。

---

## 狀況 B｜分不到 GPU

**原因**：免費版動態配額，忙碌時段會分不到。這是免費資源的本質，不是你操作錯。

**處置**：換個時段，或先用 CPU 完成不吃算力的步驟。W03 所有練習 CPU 都跑得動。

---

## 狀況 C｜`pip install pyradiomics` 失敗

這一條要講清楚，因為 W06、W08、W12 三週都靠它。

**PyPI 上的 pyradiomics 已經停更。** 最後一版 3.1.0 發佈於 2023-05-18，只提供 cp37–cp39 的 wheel。實測結果：

| 環境 | 指令 | 結果 |
|---|---|---|
| Python 3.12 | `pip install pyradiomics` | ✗ 失敗。原始碼要編譯，而 `setup.py` 用了 `configparser.SafeConfigParser`，這個類別在 Python 3.12 已被移除 |
| Python 3.11 | `pip install pyradiomics` | ✗ 失敗。建置時找不到 numpy（build isolation 的環境裡沒有） |
| Python 3.11 | 先裝 `numpy==1.26.4` 與 `versioneer`，再 `pip install pyradiomics --no-build-isolation` | ✓ 成功，但版本會被誤報成 3.0.1 |
| **Python 3.12** | **`pip install git+https://github.com/AIM-Harvard/pyradiomics.git@8ed5793`** | **✓ 成功，numpy 2.x 也相容，萃取出 107 個特徵** |

**所以共用的 `requirements.txt` 鎖定 GitHub 上經測試的 commit**：

```
pyradiomics @ git+https://github.com/AIM-Harvard/pyradiomics.git@8ed579383b44806651c463d5e691f3b2b57522ab
```

安裝：`python -m pip install -r requirements.txt`。實測從零編譯約一分鐘，Colab 可能更久。
W03 建立一次完整環境，後續週次沿用同一份清單；runtime 被回收時需重新安裝。

鎖 commit 比鎖版本號更精確 —— 版本號可以被重新發佈，commit 不行。這正是 W03 在講的事情，只是強度再上一階。

**如果你的環境只能用 Python 3.11**，走這條備援路線：

```bash
pip install "numpy==1.26.4" versioneer setuptools wheel
pip install pyradiomics --no-build-isolation      # 不要加 ==3.1.0，版號會對不上而被拒絕
```

## 狀況 D｜裝完套件後 import 失敗、或 numpy 版本打架

Colab 裝完套件常會要求**重新啟動執行階段**。重啟後請**從第一格重跑**，不要從中間接著跑 —— 重啟等於換了一台機器，記憶體裡的變數全部沒了。

這也是為什麼所有安裝指令都要留在第一格：斷線或重啟後，重跑一格就恢復，不需要任何「我手動點了一下」的步驟。

---

## 狀況 E｜同學跑不出跟我一樣的數字

依序查 `docs/04_可重現性檢核表.md` 的六個來源。九成的案例是前三個：版本、隨機、路徑。

比對版本時直接使用 `requirements.txt`。它是 Python 3.12／Linux 的完整實測快照，包含直接與
間接相依；其他平台若無法安裝，不應任意改版本，應建立並驗證該平台專用的環境清單。
